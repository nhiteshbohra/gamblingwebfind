# Change Spec: Drop Screenshot Tab from Domain Detail Panel — Live Site Only

## Goal
The domain detail drawer currently shows two tabs, **Live Site** and
**Screenshot**. Remove the Screenshot tab and its fallback logic entirely —
the panel should only ever show the live embedded site. No tab switcher, no
screenshot fetch, no `img` element.

## Why
Screenshots are a point-in-time capture that isn't kept around long-term, so
showing one as an alternative view next to the live site is redundant — the
live iframe is already the source of truth and doesn't go stale.

## Scope — what this touches
This is a **dashboard detail-panel-only** change. It does **not** touch:
- `export_domains/screenshot.py` or the Playwright capture pipeline itself.
- The `.docx` / `.pdf` / `.xlsx` compliance reports generated by
  `export_domains/exporter.py` — those are static documents that get emailed
  or archived, and they have no concept of "live" content, so they still
  need an actual image embedded in them. Screenshot capture must keep
  running for exports.
- `screenshot_taken` / `screenshot_failed_reason` fields in MongoDB, or the
  `/api/domains/{domain}/screenshot` endpoint — reports and any external
  consumer of that endpoint still depend on it.

In short: **stop showing screenshots in the live dashboard UI**, keep
generating and storing them for the report pipeline.

## Files to change

### `web/index.html`
Remove the tab switcher and the screenshot pane entirely. Replace the current
`preview-tabs` + `detail-live-area` + `detail-screenshot-area` block with just
the live iframe, no tab buttons:

```html
<div class="mb16">
  <div class="preview-tabs">
    <span class="preview-tabs-title">🌐 Live Site Preview</span>
    <button class="btn btn-ghost btn-sm preview-expand-btn" onclick="togglePreviewExpand()" title="Expand preview">⛶</button>
  </div>

  <div class="preview-pane">
    <div id="live-loading" class="preview-loading">Loading live site…</div>
    <iframe id="detail-iframe" class="detail-iframe" src="about:blank" loading="lazy"
            sandbox="allow-same-origin allow-scripts allow-forms allow-popups"
            onload="onLiveFrameLoad()"></iframe>
    <div id="live-blocked-hint" class="preview-blocked-hint hidden">
      ⚠️ This site may be blocking embedded preview (X-Frame-Options / CSP).
      If the frame stays blank, <a id="live-blocked-visit-link" href="#" target="_blank" rel="noopener noreferrer">open it directly</a>.
    </div>
  </div>
</div>
```

Delete: `tab-btn-live`, `tab-btn-shot`, `detail-screenshot-area`,
`detail-img`, `no-screenshot-msg`.

Keep: the `↗ Visit Website` link at the bottom — still the right fallback for
sites that flat-out refuse to be framed, live or not.

### `web/app.js`
- Delete `switchPreviewTab()` entirely — no more tab state to manage.
- In `openDetail()`: remove all screenshot-tab setup (`imgArea`,
  `noShotMsg`, `img.dataset.src` assignment, the `switchPreviewTab("live")`
  call at the top). Keep the iframe load + 6-second blocked-hint timeout
  logic exactly as-is — that part isn't screenshot-related.
- `onLiveFrameLoad()`, `togglePreviewExpand()`, `closeDetail()`
  (iframe cleanup on close) stay unchanged.

### `web/style.css`
Remove now-unused rules: `.preview-tab-btn`, `.preview-tab-btn.active`,
`.detail-screenshot-img`. Keep `.preview-pane`, `.detail-iframe`,
`.preview-loading`, `.preview-blocked-hint`, `.preview-expand-btn`,
`.detail-drawer.preview-expanded` — all still used by the live-only view.

## Acceptance criteria
- Opening any domain's detail panel shows only the live iframe — no tab
  buttons, no way to reach a screenshot view from the dashboard.
- No dashboard network request is ever made to
  `/api/domains/{domain}/screenshot` (confirm via browser devtools Network
  tab while clicking through several domains).
- The Playwright screenshot capture pipeline (Stage 3 / `run_export_domains`
  / `screenshot.py`) is untouched and still runs normally — exported
  `.docx`/`.pdf`/`.xlsx` reports still contain images.
- Expand (`⛶`) and the blocked-site warning banner behave exactly as before.
- `↗ Visit Website` link still works as the final fallback.
